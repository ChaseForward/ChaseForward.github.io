6.5840 distributed system

Lab 1 MapReduce

MapReduce 是 Google 提出的一种分布式数据处理框架，其核心思想在于将大规模的数据进行分片，分发到多台机器上并行计算，最后将结果合并起来。

它主要解决的问题就是在大数据时代，面对海量数据，单机不能及时处理——希望能够通过分布式并行计算以加速数据处理。

列举一些典型的应用场景

单词计数 Word Count

统计海量文档中每个单词的出现频率。

MapReduce 如何做？

  • Map 阶段: 假设每个文档都是一个 Map 任务，这个文档的内容里每出现1个单词，就输出一个 (word, “1”)
  • Shuffle 阶段: 框架自动将所有 Map 输出的中间键值对按照 Key 进行分区(相同 word 一定会分到同一个 Reduce)、排序(相同key的数据连续出现)。
  • Reduce 阶段: 对于相同的 key，收集 value, 执行 Reduce 函数，最终得到一个 key/value，将其写回磁盘。

具体实现

每个 worker 会通过 rpc 和 coordinator 进行通信。

每个 worker 会向 coordinator 请求任务，执行任务，并将任务执行完成后的中间结果写入磁盘，并通知 coordinator。

  • Map 阶段: 如果任务是 Map 类型，那么 worker 会从磁盘读取文档内容，执行 map 函数之后，在写入磁盘之前会先 shuffle^[1]。

[^1]: 这里的 shuffle 是指将 Map 输出的中间键值对按照 Key 进行分区。在具体实现中，相同的 key，也即 word 一定会写入同一文件。

  • Shuffle 阶段: 在 Reduce 之前，批量读取文件，然后排序。这里的 Shuffle 是保证 相同的 word 一定是连续的。

  • Reduce 阶段: 对于相同的 key，收集 value，执行 Reduce 函数，最终得到一个 key/value，将其写回磁盘。

除了单词计数，还有哪些实际的应用场景

  • 倒排索引 Inverted Index
    用户搜索一个词，你怎么快速找到哪些文档包含它，可以用在搜索引擎中。
    核心逻辑：

Map：每个文档 → (word, docID)
Shuffle：相同 word 聚到一起
Reduce：word → [docID1, docID2, docID3…]

  • URL 访问频率 Count of URL Access Frequency
    从海量访问日志里，统计每个 url 被请求了多少次。

Map: 每条日志 → 提取 URL，输出 (URL, 1)
Shuffle: 相同 URL 聚到同一个 Reduce
Reduce: 把同一个 URL 的 [1, 1, 1...] 加起来，输出 (URL, 总次数)

知道哪些 URL 访问最多，就能推荐热点页面。而那些访问频率高的页面，广告位更值钱。

MapReduce 中不同节点之间如何进行通信？

worker 和 worker 之间不需要通信，coordinator 和 worker 之间需要通过 Go 标准库 net/rpc 实现远程过程调用。

Worker 如何获取任务？

worker 通过 Go 标准库 net/rpc 向 coordinator 发出请求，因为实验实在本地测试，所以 worker 可以直接读文件，并将任务执行完成的结果落回磁盘。

最终结果如何汇总得到？

map 任务执行结束后会先对中间结果进行分区，保证相同 key 的 所有 value 会落入一个中间文件。当所有 map 任务都执行结束后，reduce 才会批量读取分配给它的中间文件，对中间结果进行排序，这样做可以保证相同的 key 是连续的，然后调用 reduce 即可汇总得到最终的结果。

如果一个 worker 失败了，那么会如何处理？

  1. 超时检测
    coordinator 会定时检查每个正在运行的任务是否执行超时(实验设置的固定时间是10s)，如果超时了，那么就会认为这个 worker 失败了，然后重新将这个相同的任务加入到待分配的任务队列中。
  2. 数据一致性保障
    map/reduce 的输出文件不是最终写文件名，而是先写临时文件，写入内容，等到写完，关闭文件之后再通过原子操作重命名。这样做的原因是，考虑到 worker 崩溃时，临时文件可能不完整，只有完整的文件才会被使用。

实验是在真实分布式环境测试还是仅在本地测试？

虽然是在本地测试，但是从实验角度来看，它模拟了完整的分布式行为，无论是 coordinator 还是 worker 都是独立的操作系统进程，它们之间不共享内存，完全通过 Unix Domain Socket(RPC) 和 文件系统进行通信。在真实的分布式系统中，换成 TCP 通信 + 分布式文件系统就能直接部署到多机集群。
