关于 static 关键字

static用于定义 静态变量 和 静态函数。

static 定义的静态局部变量

特点:

  1. 初始化: 默认执行零初始化，显示初始化只会执行一次
  2. 生命周期: 程序运行时分配内存，程序结束时才销毁
  3. 若定义在函数内部，则只在该函数内部可见

Question 1

为什么 static 定义的静态变量只被初始化一次？且生命周期持续至程序结束时才销毁？

Answer 1

关于这一点，我想我们有必要理解cpp编译连接后可执行程序是如何划分的。

  1. (.text)代码段: 存放只读的机器指令
  2. 数据段:
    $$ \textbf{数据段} \begin{cases} \text{(.rodata)只读数据段: 存放字符串常量、constexpr 常量、 编译期可确定值的全局 const 常量} \\ \text{(.data)数据段: 有非零初始值的全局变量、static静态变量} \\ \text{(.bss)未初始化数据段: 未显式初始化(默认 0)的全局变量、static 变量 (ELF 中不占磁盘空间，加载时由 OS 清零)} \\ \end{cases} $$
    其中: 数据段和未初始化数据段属于进程的 静态存储区，在进程被创建时分配、进程退出时释放。

回到我们刚才的问题，在上述那段代码中，static 定义的 var 变量被分配在数据段(静态存储区)，因此在程序运行时执行初始化，在程序结束时才会被销毁。

static 定义的静态全局变量

特点:

  1. 具有文件作用域，其他源文件无法访问
  2. 生命周期持续至程序结束时才销毁

Question 2

如何理解 static 定义的全局变量具有文件作用域？有什么应用场景吗？

Answer 2

举个例子。

因此，通过简单验证可知，static 定义的全局变量具有文件作用域，其他源文件无法访问。具体而言:

  1. cpp 每个.cpp是独立编译单元，编译生成.o目标文件，符号分两种链接属性: 内部链接、外部链接。
  2. 普通全局变量默认外部链接: 符号写入符号表并对外导出，支持跨文件共享，extern关键字仅声明变量，不分配内存，依赖其他编译单元的定义完成链接。
  3. static修饰全局变量/函数会修改链接属性为内部链接，符号仅本编译单元内部可见，不会对外导出，其他文件无法通过 extern访问，用来解决多文件同名全局符号冲突。

嗯，底层机制很复杂，但是面试官一般来说不会打破砂锅问到底，我们只是需要知道:
cpp1 定义了 static 全局变量，那么cpp2是无法通过extern关键字访问该静态全局变量，所以我们常说static定义的全局变量具有文件作用域。

static 在类中的应用

static 定义的静态成员变量

特点:

  1. 初始化: 类内声明，类外初始化
  2. 生命周期: 程序运行时分配内存，程序结束时才销毁
  3. 作用域: 类作用域，相当于类域中的全局变量，被类的所有对象所共享，包括派生类的对象

static 定义的静态成员函数

特点:

  1. 不能调用非静态成员变量或者非静态成员函数，因为静态成员函数没有 this 指针。静态成员函数可以视为类作用域下的全局函数。
  2. 静态成员函数不能声明为虚函数(virtual)、const函数和volatile函数。
