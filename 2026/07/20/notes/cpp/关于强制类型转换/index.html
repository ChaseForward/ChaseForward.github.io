关于 C++ 中的强制类型转换

C++ 提供了四种强制类型转换运算符，它们各自具有明确的适用场景和安全级别。相比 C 风格的强制类型转换，这四种转换能够更准确地表达程序员的意图，也更容易被编译器检查。

2. 主要适用场景

基本数据类型之间的转换

指针或引用的向上转换（派生类 -> 基类）

向上转换始终是安全的，因为派生类对象一定包含一个完整的基类子对象。

指针或引用的向下转换（基类 -> 派生类）

static_cast 在进行向下转换时不会进行运行时检查。如果 pb 实际上并不指向一个 Derived 对象，那么程序的行为就是未定义行为（Undefined Behavior，UB）。

如果需要在运行时验证对象的真实类型，应使用 dynamic_cast。

4. 小结

static_cast 用于执行真正意义上的类型转换。

它能够在编译期检查转换是否合法，但对于以下情况不会进行运行时检查：

  • 基类 -> 派生类（向下转换）。
  • void* 与具体类型指针之间的转换。

因此，这两种场景需要程序员自行保证类型正确。

  • 底层内存操作。
  • 操作系统开发。
  • 驱动开发。
  • 网络协议解析。
  • 序列化与反序列化等场景。

日常业务开发中应尽量避免使用。

  • 如果对象本身就是 const，去掉 const 后再修改对象，将导致未定义行为。

因此，const_cast 只能改变类型的限定符（Qualifier），不能改变对象本身是否真正是常量。

因为运行时类型信息（RTTI, Run-Time Type Information）依赖于虚函数表（vtable）。

只有存在虚函数表，程序在运行时才能确定对象的真实类型，从而判断转换是否安全。

Summary

运算符 是否检查运行时类型 主要用途
static_cast ❌ 常规类型转换、数值转换、继承体系中的向上转换，以及需要程序员保证安全性的向下转换。
dynamic_cast ✅ 多态类型之间的安全向下转换，运行时验证对象真实类型。
const_cast ❌ 添加或移除对象的 const 属性，不负责类型转换。
reinterpret_cast ❌ 将同一块内存按另一种类型重新解释，主要用于底层内存操作。
  • static_cast用于普通类型转换，做编译期检查，但不保证运行时安全(如基类强转为派生类，void*转换为其他类型的指针)。
  • dynamic_cast主要用于多态类型之间的安全转换，即基类至少要有一个虚函数。它会在运行时检查对象的真实类型，失败返回 nullptr（指针）或抛出 std::bad_cast（引用）。
  • const_cast用于添加或移除对象的 const 属性，不改变对象的实际类型。
  • reinterpret_cast将对象按另一种类型重新解释，风险最高，用于底层开发。
